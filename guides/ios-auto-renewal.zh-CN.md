# PicHarbor iOS 自动续签教程

[English](ios-auto-renewal.md) | **简体中文** · [返回项目介绍](../README.zh-CN.md)

更新日期：2026-11-19。适用于 PicHarbor Mobile 集成的 SelfRefreshKit。

PicHarbor iOS 内置 [SelfRefreshKit](https://github.com/Cc-Cece/SelfRefreshKit)。首次用电脑完成签名安装和设备配对，再完成手机内的续签设置，之后可通过快捷指令自动在 iPhone 上续签，正常使用不需要每周重新连接电脑。

这里的「一次」指首次配置流程；恢复手机、丢失配对记录或无法恢复签名环境等情况，可能需要再次使用电脑。自动续签依赖网络、Apple 会话与本地回环 VPN，并不是永久有效的证书。

## 一、准备

| 设备／文件 | 用途 |
| --- | --- |
| iOS 17+ 的 iPhone | 安装和运行 PicHarbor |
| Windows 电脑与数据线 | 首次签名安装、写入设备配对记录 |
| PicHarbor 未签名 IPA | 从 Mobile 仓库成功的 Actions 运行下载，或使用已交付的对应版本 |
| SelfRefreshSetup 工具 | 从 SelfRefreshKit Releases 下载，当前提供的可执行文件名为 `SelfRefreshKit.exe` |
| Apple 设备或 iTunes | 为 Windows 提供设备驱动 |
| .NET 10 Desktop Runtime | 当前 Windows 工具发布版所需；按下载版本的说明安装 |
| Apple 账号 | 签名及手机端续签使用；按引导完成认证和双重验证 |
| LocalDevVPN | 在手机上提供续签所需的本地回环网络 |

官方入口：

- [PicHarbor Mobile 构建](https://github.com/Cc-Cece/PicHarbor-Mobile/actions)
- [SelfRefreshKit 发布下载](https://github.com/Cc-Cece/SelfRefreshKit/releases)
- [SelfRefreshSetup 使用说明](https://github.com/Cc-Cece/SelfRefreshKit/tree/master/tools/SelfRefreshSetup)
- [LocalDevVPN](https://apps.apple.com/app/localdevvpn/id6744003051)

手机按安装引导启用开发者模式，解锁并信任电脑。配对记录属于设备凭据，只保留在自己的设备或安全备份中。

## 二、电脑上完成首次安装和配对

1. 通过数据线连接 iPhone，保持解锁；出现提示时选择「信任此电脑」。
2. 打开 `SelfRefreshKit.exe`，选择 PicHarbor 的未签名 IPA。
3. 按界面要求填写并保存 Apple 账号；不要把 Google 账号填到这里。未有特别配置时，Anisette 地址按工具默认设置处理。
4. 刷新设备列表，选中本机 iPhone。
5. 执行「签名、安装并写入配对」；英文界面为 **Sign, Install and Write Pairing**。如果选择的是已签名包，按钮可能为 **Install and Write Pairing**。
6. 如需 Apple 验证码，在工具出现的验证码输入框提交。
7. 等待安装和配对写入都成功，不只确认应用图标已经出现。

工具会根据系统处理配对记录：iOS 17.4+ 使用 RPPairing，较早版本使用对应的 Lockdown 配对记录。无需自己把一种文件改名伪装成另一种。

写入后，退出 PicHarbor 再重新打开，以加载新的配对信息。如系统要求信任开发者，按设备设置提示完成。

正常情况下，到这里即可断开数据线，继续下面的手机配置。如果应用内仍找不到配对记录，先保持连接，检查工具日志并重新写入。

## 三、在手机内完成续签设置

从 PicHarbor 的「设置」进入 SelfRefreshKit 续签页面，再打开「必需操作」。界面名称随语言和组件版本可能稍有区别。

| 项目 | 要检查什么 |
| --- | --- |
| 导入设备配对文件 | 显示已完成，设备信息与当前 iPhone 对应；工具已写入时通常无需再手动导入 |
| 登录 Apple 账号 | 显示已认证；建议继续使用首次签名的同一账号及开发者团队 |
| 本机续签设置 | 按界面提示完成本机接管，或由已有的成功描述文件刷新记录确认完成 |

在 LocalDevVPN 中允许添加 VPN 配置并连接。它提供的是续签使用的本地回环网络，不等于 PicHarbor「应用内代理」中的 Google 访问节点。

如果第三项仍提示「待接管」，按提示选择**当前 PicHarbor 应用对应的未签名 IPA**，在手机上完成重签和覆盖安装。这个步骤可能暂时退出应用，完成后重新打开检查；不要为完成它先卸载现有应用。

当前版本也会识别实际成功的描述文件刷新记录。如果已经成功续签并正确显示完成，无需仅为了再做一遍流程而重复覆盖安装。旧版曾存在第三项状态未更新的问题，不能只凭旧版的 2/3 提示判断实际续签失败。

## 四、先验证一次手动续签

1. 连接 LocalDevVPN，确保手机能访问需要的网络服务。
2. 在续签页面打开「健康状态检查」，运行检查。
3. 检查设备配对、本地回环网卡（`10.7.0.1`）、Anisette 服务和 Apple 开发者会话。
4. 返回主页面，点「立即续签」。
5. 确认显示成功，并核对最近续签时间和新的到期时间。

免费账号的有效期通常会回到接近 7 天；例如刚续签后显示约 `6d 23h`。应同时核对成功结果、时间和健康状态，不能只凭应用仍能打开就认定续签成功。

确认这一步正常，再配置自动化。手动刷新不通过时，先解决对应的配对、网络或账号问题。

## 五、设置快捷指令自动续签

可以从应用内「可选操作 → 配置自动续签快捷指令」查看引导或获取预设。预设可能更新，以应用内和上游项目当前入口为准；导入后确认续签动作指向 **PicHarbor**。

也可以自行创建：

1. 打开 iPhone「快捷指令 → 自动化」，新建「特定时间」个人自动化。
2. 建议每 **5 天**续签一次，选择常用的时间，开启「立即运行」，避免依赖临时手动确认。从上次成功续签起，间隔不能超过 **7 天**，否则需要重新连接电脑恢复签名安装。
3. 按顺序添加以下动作：

   ```text
   连接 LocalDevVPN
       ↓
   等待 2 秒（给本地隧道准备时间，可按实测调整）
       ↓
   PicHarbor：刷新应用签名描述文件
   / Refresh App Provisioning Profile
       ↓
   等待 5 秒（按实际完成情况调整）
       ↓
   断开 LocalDevVPN
   ```

4. 手动运行这条快捷指令，完成首次权限提示，确认其成功后再交给自动化触发。
5. 下次触发后，回到 PicHarbor 核对最近续签时间和有效期。

动作支持后台运行，无需特意加入「打开 PicHarbor」。首次授权、Apple 重新认证或验证码仍可能需要手动处理。若设备上其它 VPN 与 LocalDevVPN 冲突，应先处理冲突再测试。

每 5 天续签可在 7 天有效期内留出失败后的补救时间。间隔应从上次成功续签起计算，而不是从自动化上次触发起计算。自动化是否按时运行仍受 iOS 执行条件影响，应偶尔查看结果。

## 六、常见问题

| 现象 | 处理方式 |
| --- | --- |
| 电脑找不到手机 | 解锁、确认信任、检查数据线和 Apple 驱动，然后刷新设备列表 |
| 安装成功，但应用内没有配对记录 | 检查是否完成「写入配对」，退出重开应用；必要时重新连接电脑写入 |
| 本地回环网络未连接 | 打开 LocalDevVPN 并连接，重新运行健康检查；应用内代理开关不能替代它 |
| Apple 会话失效或要求验证码 | 在手机续签页面重新认证；后台动作不能替你完成交互式验证码 |
| 手动成功，自动化失败 | 检查「立即运行」、所选动作所属应用、首次授权及 VPN 是否已就绪 |
| 剩余时间持续减少 | 检查最近成功时间和失败提示，手动运行续签，不要仅确认自动化开关存在 |
| 配置后是否还要每周连电脑 | 正常续签不需要；配对或签名环境失效且无法在手机恢复时才重新使用电脑 |
| 续签与升级有什么区别 | 日常续签刷新当前安装的有效期；安装新版 IPA 则是应用更新，不是同一个动作 |
| 超过 7 天未成功续签，应用已过期 | 重新连接电脑恢复签名安装，优先保留原应用数据 |

## 七、完成检查清单

- [ ] 首次签名安装与设备配对写入均成功。
- [ ] 应用内配对与 Apple 账号状态正常，本机续签设置已完成。
- [ ] LocalDevVPN 和健康状态检查通过。
- [ ] 至少一次手机手动续签成功，有效期已更新。
- [ ] 快捷指令手动运行成功，动作指向 PicHarbor。
- [ ] 已配置每 5 天续签，间隔不超过 7 天，并检查过实际触发后的续签结果。
