# Android 应用内代理测速与连接修复

版本：`2.0.0-alpha.5` / versionCode `5`。保留现有 Android 页面框架与用户配置，iOS 和共享 gpmc 核心不变。

## 原因及修复

Clash 控制器中的节点名称位于 URI 路径段。旧实现直接使用表单编码，空格变成 `+`，而核心按路径规则解码，导致带空格的节点名称无法匹配。测速失败后节点进入五分钟不可用状态，自动连接选择也因此被阻断。

现在按独立路径段编码，空格使用 `%20`，字面加号使用 `%2B`，同时处理中文、斜杠、百分号等字符。代理启动与控制请求明确放在 IO 调度器；测速等待加密配置加载完成，并以原子状态阻止重复启动。无效延迟响应不再被误记为成功，取消后也不再更新当前测试结果。

## 实机验证

用户本次明确授权连接手机测试、修复与安装，取代上轮只编译的限制。本次为手动安装，30 分钟自动安装任务仍保持 Disabled。

在同一手机、同一份已保存配置上进行对照：

| 项目 | 修复前 | 修复后诊断构建 |
| --- | --- | --- |
| 节点数 / 名称带空格 | 2 / 2 | 2 / 2 |
| 应用测速成功数 | 0 | 2 |
| 独立使用正确路径编码测速成功数 | 2 | 2 |
| 经应用内本地代理访问 Google HTTPS | 节点不可用，连接失败 | 返回预期 HTTP 204 |

验证要求路由为 `127.0.0.1` 上的应用内代理，不接受直连回退作为成功。测试不导出订阅链接、节点服务器、凭据或账号，不上传照片。

路径编码回归测试 2 项通过，覆盖空格、加号、中文、emoji、斜杠、百分号、井号和问号等名称。共享核心及平台适配器固定来源核对通过。

从主线程调用代理连接的实机回归也通过：两个节点均健康，应用内代理 HTTPS 返回 204。最终签名 Release 已覆盖安装为 versionCode 5；保留原有应用数据，未重新导入配置。签名和 APK 内容静态核对通过。

用户解锁后，已在正式版应用内代理页面再次点击“测速全部节点”：两个节点分别显示 **547 毫秒、587 毫秒**，页面提示“测速完成”，没有“不可用”项。当前应用进程日志未发现崩溃或主线程网络异常。

`ProxyDeviceTest` 仅在明确选择该测试类并传入 `phase=proxy_acceptance` 时运行。设备测试构建使用 `-PdeviceTestBuildType=diagnostic`；测试 APK 与应用使用原有签名。补齐设备测试的 Compose BOM 和依赖锁定，不升级现有运行时依赖。
