# iOS 冷启动账号恢复

iOS 0.2.41（45）。不修改 Android，不安装到设备，不连接真实账号验证。

此前默认账号只保存在 UserDefaults；凭据保存在 Keychain。容器设置丢失时，启动会查找旧版 credential 槽，无法恢复已经按账号保存的凭据。另一个缺口是启动时网络认证只执行一次，临时网络或代理失败后，即使网络恢复也不会再次连接。用户仍能在账号列表选择并登录，与这两条路径一致；没有设备日志，无法断言本次具体由哪条触发。

现在成功登录时将当前账号选择一并保存在同一访问权限的独立 Keychain 服务。旧版先使用有效的 UserDefaults 选择，缺失时仅在恰好一个账号的情况下自动恢复；多账号没有明确选择时不猜测。原 credential 槽仍可读取。主动退出写入明确的退出标记，避免恢复另一保存账号，账号显式选择仍可用。

临时网络、代理或 Keychain 可访问性问题不会清除保存凭据。账号为空且队列空闲、网络可用时，通过现有前台/网络变化/10 秒调度恢复入口按至少 30 秒间隔重试。永久认证错误停止自动重试，手动登录失败也停止旧身份恢复，避免切换失败后意外恢复旧账号。恢复成功后重新载入该账号设置和任务视图。已有账号时不自动弹出新账号导入页面。

只保留账号选择，不在普通偏好、日志或测试报告中保存凭据。重新签名若更换 Team / Keychain access group，旧钥匙串不可访问，不能通过本修复绕过系统隔离；用户所述可列出并重新选择账号的情况说明凭据仍可访问。

验证：iOS 离线 Python 套件；macOS CI 的 23 项账号选择、明确退出、容器偏好丢失、多账号歧义、旧槽兼容和真实 Keychain 存取检查；完整未签名 IPA 编译与包内容检查。未执行实际重签安装、设备冷启动或真实 Google 认证。
