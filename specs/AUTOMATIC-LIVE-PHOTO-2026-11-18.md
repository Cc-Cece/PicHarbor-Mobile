# 按文件自动选择 Live Photo 备份方式

版本：Android 2.0.0-alpha.15（15），iOS 0.2.38（42）。两端继续使用各自原生界面和既定页面框架。只编译，不安装。

## 行为

- 新设置、恢复默认值使用“自动（推荐）”。已有明确选择及旧任务不被升级重写。
- 普通照片、视频直接上传；经共享解析器验证的内嵌动态照片保留原文件，不重新封装。
- 完整照片/视频资源按原始配对提交。Android 依据一致的 Apple 内容标识，支持从 iOS 迁入的文件；候选必须双向唯一，同目录用于消除重复版本歧义，名称或时间相近不能证明配对。
- iOS 使用 Photos 提供的资源关系，分别处理原始/编辑后版本，不跨版本拼接。经导出的普通文件也会检查内嵌动态结构。尚未由 Photos 关联的独立资产不凭名称推断关系，保留原文件。
- 标识存在但资源不全、配对歧义或动态结构不明确时，保留可读取的文件，并展示“已保存 · 动态部分未确认”及具体说明；读取失败、权限及网络错误仍正常报错，不据此降级。
- 自动模式不会把成对资源强制合成为 Motion Photo，也不会因为网络失败自动改成静态备份。
- “手动”下提供高级实况设置：原始配对、兼容封装；分步上传作为配对的提交兼容选项。

## 持久化与恢复

共享核心提供纯规划接口 `plan_live`，输出资源指纹、表示形式、配对及警告；不执行上传。两端在提交前保存每项识别结果。Android Room 9→10 增加 `items.livePlan`，原任务策略仍为原值，只能首次写入规划；iOS 在任务清单保存规划及导出资源摘要。

自动配对会在提交前确定联合/分步路由。Android 写入与照片/视频 SHA256 绑定的独占、落盘检查点；iOS 复用已持久化的 pair route。重试不因云端状态改变而切换路径，结果不确定时沿用原提交围栏查询；不盲目重复提交。

核心来自 canonical gpmc；通过 `tools/sync-core.py --source ../gpmc` 同步两端并验证锁文件，未直接修改生成快照。

## 验证

- canonical core 显式离线套件：50 项通过（含 12 项自动规划/路由测试）。未运行涉及真实云端写入的旧集成测试。
- Android 相关单元测试：27 项通过，包括 5 项自动模式/迁移测试、原配对行为、取消记录和面板生命周期回归。
- iOS Python 适配/本地化套件：87 项，86 通过、1 项跳过。增加 Swift 自动策略、旧值解码、规划序列化及来源变更测试；当前 Windows 环境未运行 XCTest。
- Android 翻译源扫描：685 条中文界面文本，无缺失。两端新增文案包含简体、英文和香港繁体/粤语资源。
- Android 签名 release 与 iOS 未签名 IPA 的构建、包内容校验及摘要记录在本轮 delivery 清单。没有手机安装或真实 Google 相册动态效果验收；云端实际支持情况仍需用户少量照片测试。
